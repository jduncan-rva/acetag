# Tag format

`SpoolTag.buildTag(Spec): Pages` encodes, `SpoolTag.decode(Pages): Spec?` decodes. The layout is
reverse-engineered (Molodos/anycubic-nfc-filament), not specified, and the only real test of it
is a printer reading a sticker. A wrong byte is found after the sticker is on a spool.

## What can't move

- **Pages 0x04–0x27 only.** 0x00–0x03 and 0x28 onward are the NTAG213's UID, lock and config
  pages; writing them can make a sticker read-only or unreadable. `Pages` refuses any page outside
  that range. Keep it that way.
- **`0x7B` at page 0x04 byte 0** is what makes a tag a spool. `decode` returns null without it.
- **`0x4D` at page 0x27 byte 3** is on everything this app writes and on no genuine dump.
  `isCustomWritten` reads it so a scan can tell "a spool I've never seen" from "a sticker I wrote
  that's on no spool". A released sticker still decodes, so callers check the marker **before**
  the decode result.
- **Page 0x20 holds the group id**, the same 4 random bytes on both stickers of a pair. It is zero
  on genuine tags. It's written for the format's sake and never matched on (see AGENTS.md).
- **The SKU at page 0x05 comes from `FilamentMaterial.skuForTagType`**, never from free text.
  The ACE validates it (see the `materials` skill).
- Little-endian u16s, and a u16 starting at byte 3 spills into byte 0 of the next page.
  Colour is stored A, B, G, R. Diameter is hundredths of a mm.

## Tests

`SpoolTagFormatTest` pins whole-tag hex for two specs. The expected strings were generated by
`scripts/spool_tag.py`, a separate encoder of the same layout. If you change the layout on
purpose, change it in both, regenerate the strings from the Python side, and never paste the
Kotlin output in as the expectation. Pinning the encoder's own output proves nothing.

Neither encoder is a genuine dump. Any layout change needs a person to write a sticker and load
it in an ACE before merging. Say so in the PR.

## The NFC path

- `Type2Tag` sends raw Type 2 READ/WRITE over `NfcA.transceive`. Don't switch to
  `MifareUltralight`: genuine Anycubic tags report only `NfcA` (seen on a Pixel 9 Pro XL), so that
  API silently never matches. `NfcActivity` filters on `NfcA` for the same reason.
- An Android `Tag` is dead once it leaves the field. Nothing can write to a tag after a dialog,
  a coroutine hop that waits on the user, or a second tap. Do every write inside the tap that
  delivered the `Tag`.
- None of this runs off a device. Unit tests cover `SpoolTag`, and `TagIo`/`Type2Tag` are covered
  only by a person tapping a sticker.
